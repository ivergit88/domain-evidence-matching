# Как я подошёл к задаче

Я бы начал с конкретного требования. Для него можно описать, какие факты в опыте кандидата будут достаточным подтверждением.

Например, для интеграции банковского ядра нужны действие и объект в банковском контексте. Общий опыт работы в банке подходит для поиска, но сам по себе не отвечает на этот вопрос. Поэтому я разделил поиск похожих фраз и проверку фактов.

В этом варианте нет общего графа доменов. Вместо него есть небольшая карточка для каждого требования. В карточке указаны нужные признаки, варианты формулировок и слова, по которым стоит просмотреть опыт. Последние только помогают поиску и не дают подтверждения.

Важная деталь: признаки проверяются внутри одной исходной фразы. Простые части предложения тоже разделяются, чтобы не переносить действие с одного объекта на другой. Нельзя взять интеграцию из проекта с CRM, а банковское ядро из другого проекта и объявить, что человек интегрировал банковское ядро. В SQL нет информации о проектах, поэтому здесь каждая фраза проверяется отдельно. Это простая проверка слов и коротких фраз. Она не заменяет разбор смысла сложного резюме.

Для резюме я бы сохранял цитату и её связь с проектом. LLM могла бы извлекать такие факты и предлагать условия карточки. Затем нужно проверить, что цитата есть в тексте, относится к нужному проекту и не отрицает опыт. В текущем примере используются готовые фразы из SQL, поэтому этот этап не проверяется.

Обязательное требование должно получить подтверждение. Желательное требование помогает расставить кандидатов по местам. Если данных недостаточно, результат остаётся на уточнение. Так мы не выдаём общую тематику за конкретный опыт.

Для начала я сравнил поиск по словам, поиск по эмбеддингам и проверку по карточке. Взял несколько примеров из SQL и заранее отметил подходящие и спорные случаи. Проверка помогает на этих примерах, но их мало. Для следующего опыта нужны новые запросы и резюме, которые не использовались при написании правил.

Для 10 000 кандидатов фразы и векторы можно хранить заранее. При новом запросе сначала выполняется поиск, а затем проверяются найденные фрагменты. Карточка относится только к запросу, поэтому не нужно сначала строить общий справочник всех возможных доменов.

Слабое место подхода тоже видно: условия карточек сейчас написаны вручную. Если формулировка новая, подтверждение можно пропустить. Автоматическое составление карточек через LLM я бы проверял отдельно, с цитатами и возможностью оставить спорный случай человеку.
