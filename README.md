# Сопоставление бизнес-доменов

Я бы начал с конкретного требования вакансии. Работа в банке и интеграция банковского ядра связаны, но первое ещё не подтверждает второе. Поэтому сначала нужно найти похожий опыт, а затем проверить, что именно делал кандидат.

Из резюме через LLM я бы выделял действие, объект работы и проект, сохраняя исходную цитату. Из запроса выделял бы обязательные и желательные условия. Для нового требования достаточно описать признаки нужного опыта, без заранее составленного списка всех возможных доменов.

Похожие фрагменты искал бы по словам и эмбеддингам. Затем проверял бы связь действия с объектом, учитывая отрицания и контекст проекта. Обязательные условия требуют подтверждения, желательные влияют на порядок кандидатов. Если информации не хватает, оставлял бы вопрос на уточнение.

Для 10 000 кандидатов факты и векторы можно подготовить при загрузке резюме. На запросе останутся поиск и проверка найденных фрагментов. Качество я бы оценивал на отдельной разметке специалистов: сколько подходящих кандидатов найдено, насколько правильно они расставлены и как часто ошибочно подтверждается обязательный опыт.

В коде проверена часть подхода на SQL из задания: 117 кандидатов и 695 упоминаний. Есть сравнение поиска по словам, эмбеддингов и проверки по ручным условиям. Полных резюме в данных нет, поэтому извлечение через LLM здесь не проверялось.
