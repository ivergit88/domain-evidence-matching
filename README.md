# Бизнес-домены в скоринге

Задача — понять, есть ли у кандидата нужный опыт, когда формулировки в резюме и вакансии не совпадают. «Интеграция банковского ядра» и «банковские интеграции» близки, но вторая фраза не подтверждает работу с ядром. Поэтому я разделяю поиск и проверку: сначала нахожу похожие фрагменты, потом смотрю, есть ли в них сам факт.

Из резюме извлекаю факты: действие, объект, домен, проект. К каждому — цитата и, если есть, период. Это можно делать LLM со структурированным ответом, но цитату и привязку к проекту надо проверять отдельно: модель ошибается на отрицаниях и любит склеивать действие из одного проекта с объектом из другого. Из запроса собираю карточки требований: обязательное или желательное, какие признаки подтверждают опыт, какие формулировки похожи и что отправлять на ручную проверку. Карточки лежат отдельно от кода и могут версионироваться; полный справочник доменов заранее не нужен.

Поиск гибридный: нормализованные слова и сокращения (MES, АБС) плюс эмбеддинги отдельных фрагментов. Дальше проверка по карточке: подтверждено, отрицается, данных нет или нужно посмотреть вручную. Косинус сам по себе требование не подтверждает. В скоринге сначала обязательные пункты, потом желательные. Неизвестный обязательный опыт не считается подтверждённым, а отрицание хранится отдельно от отсутствия данных. Для 10 000 кандидатов извлечение и векторы считаются при загрузке резюме, на запросе остаются разбор требований, поиск и проверка спорных пар.

В репозитории — MVP на SQL из задания. В нём 117 кандидатов и 695 уже извлечённых фраз; полных резюме, проектов и периодов нет. Карточки заданы вручную, чтобы проверить сам принцип, а не автоматическое составление. Поэтому здесь проверена только часть схемы: карточки, лексический поиск, эмбеддинги и ранжирование. На 10 сценариях с 34 оценками nDCG@2 получился 0.957 у поиска по словам, 0.918 у эмбеддингов фраз и 0.983 у проверки по карточке. Это маленькая авторская разметка, а не независимый тест. Извлечение из резюме и LLM-проверка не запускались: для них нужны полные документы.

## Запуск

Без модели и лишних зависимостей:

```bash
python -X utf8 experiment.py --offline
python -m unittest discover -s tests -v
```

Полный прогон с эмбеддингами:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -X utf8 experiment.py --benchmark 10000
```

Модель `paraphrase-multilingual-MiniLM-L12-v2` работает локально на CPU, первый запуск скачивает около 235 МБ. Результаты пишутся в `results/experiment.json` и `results/metrics.csv`.

Подробнее про данные и границы эксперимента — в [approach.md](approach.md). Выполненные ячейки — в [solution.ipynb](solution.ipynb).
