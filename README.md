# Поиск кандидатов по требованиям вакансии

Я попробовал проверять конкретный опыт по карточке требования. В ней записано, какие признаки нужно найти в исходном тексте. Для интеграции банковского ядра это интеграция, ядро и банковский контекст. Все три признака должны встретиться в одной фразе.

Сначала поиск по словам или эмбеддингам находит похожий опыт. Затем карточка проверяет, хватает ли фактов. Например, у кандидата №79 есть "интеграция банковского ядра", а у №6 только "банковские интеграции". Во втором случае нужно уточнение.

Общий граф доменов здесь не строится. Каждое требование проверяется отдельно. Новую карточку можно добавить без перестройки связей между всеми доменами.

## Что посмотреть

[Блокнот с выполненными ячейками](solution.ipynb) показывает весь пример. [Короткое описание](approach.md) объясняет выбор подхода. В [результатах](results/experiment.json) есть выдача, подтверждающие фразы и замеры.

В SQL 117 кандидатов и 695 упоминаний. Это уже готовые признаки. Полных резюме и описаний проектов в данных нет. Файл лежит в `data/domains.sql`.

## Как устроен пример

`cards.json` хранит условия проверки, `request.json` задаёт обязательные и желательные требования. В `matcher.py` находится сама проверка. `search.py` ищет похожие фразы. `experiment.py` сравнивает три варианта и сохраняет результаты.

Обязательный опыт требует подтверждения. Желательный опыт даёт преимущество в выдаче. Если не хватает данных, система оставляет статус "нужно уточнить". Высокая похожесть не меняет этот статус.

В примерах с отрицанием и разными проектами используются отдельные искусственные фразы. Они отмечены в блокноте и тестах. Простые правила не умеют надёжно разбирать любые отрицания в настоящих резюме.

## Как запустить

Нужен Python 3.12. Для примера без модели достаточно стандартной библиотеки:

```bash
python experiment.py --offline
python -m unittest discover -s tests -v
```

Для локальных эмбеддингов:

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python experiment.py
.venv/Scripts/python build_notebook.py
```

На Linux и macOS путь к Python будет `.venv/bin/python`.

При первом запуске загрузятся открытые веса MiniLM, около 235 МБ. Дальше модель работает локально на CPU. Платные API и вызовы LLM не используются. Блокнот уже выполнен, для чтения запускать его не нужно.

## Что получилось и чего пока не хватает

В 10 авторских сценариях проверены 34 выбранные пары. nDCG@2 составила 0.957 для поиска по словам, 0.918 для эмбеддингов и 0.983 для проверки по карточке. Это маленький набор примеров, а не доказательство качества на новых резюме. Условия карточек и проверочные примеры относятся к одним темам.

Правила задаются вручную. Они могут пропустить новую формулировку. Для проверки извлечения и качества на новых запросах нужны полные резюме и отдельная разметка. Следующим шагом я бы проверил LLM, которая предлагает карточку и цитаты для неё. Здесь такой запуск не выполнялся.

Замер на 10 000 профилей повторяет исходные 117 записей. Он измеряет проверку карточек, но не обработку новых резюме и не время извлечения через LLM.

В исходном SQL повреждена оболочка списков. `data.py` исправляет этот конкретный формат. Он читает SQL как текст и ничего не выполняет в базе. Исходный файл не меняется.
